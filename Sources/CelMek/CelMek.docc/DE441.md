# Native DE441 files

The first supported file format is JPL's **native little-endian DE441 binary
export**, with 8,144-byte records and the 1,018-double coefficient profile.
This is the `linux_*.441` format supplied by
[JPL's planetary ephemeris export service](https://ssd.jpl.nasa.gov/planets/eph_export.html).
It is distinct from SPICE SPK (`.bsp`) kernels. SPK types 2/3/21 are supported by the
separate <doc:SPICE_KERNELS>; neither reader requires a C library.

`DE441Ephemeris` is an explicit URL-based, low-level reader. Opening validates
the DE number, byte order, coefficient layout, extended layout, physical
constants, binary coverage and first/last coefficient-record spans. The current
profile includes planetary/lunar coordinates, nutation and lunar libration
coefficients, with no extended lunar angular-velocity or TT–TDB coefficients.
Different DE numbers, SPK, big-endian exports and different layout profiles
are rejected rather than guessed. Shorter exports using the same validated
profile are supported; file length must match its own binary coverage.

```swift
let reader = try DE441Ephemeris(url: fileURL)
let info = reader.metadata
let earth = try reader.vector(
    target: .earth, center: .solarSystemBarycentre, at: 2_451_545.0)
```

The `vector` overload with integer identifiers is retained for JPL `testpo`
compatibility; `DE441Body` provides named identifiers. These numbers are **not
NAIF IDs**. Earth is reconstructed from the Earth–Moon barycentre and stored
geocentric Moon using the file's EMRAT. Moon barycentric coordinates are then
Earth plus that geocentric vector. Mercury/Venus represent their centres;
Mars through Pluto represent planetary-system barycentres. Centre subtraction
is explicit. Queries use TDB Julian dates and return position in AU and
velocity in AU/day, as required by JPL's reference test. Nutation returns
radians and radians/day. These low-level units differ from the common SI
`CartesianState` contract; use `DE441StateProvider` for that contract.
Axes are ICRF; the output origin is the explicitly selected centre.

`DE441FileMetadata` exposes the DE number, titles, native TDB coverage, record
length/count/duration, file size, available body identifiers, coefficient
availability, frame/time convention, AU in kilometres, EMRAT and named
constants. Constants retain JPL's native units; the dictionary does not imply
that every constant is SI or a sourced `GravitationalParameter`.
Libration coefficient availability is inspectable but there is currently no
public libration interpolation query. The reader uses file AU and EMRAT
values; its static values remain the nominal DE441 constants for compatibility.

The binary header and coefficient records determine coverage. Title strings,
`header.441` and `testpo.441` can describe the larger parent ephemeris rather
than a subset export. For the locally supplied `linux_m13000p17000.441`, binary
coverage is JD **-3027215.5 through 7930192.5 TDB**, while the ASCII header and
testpo extend further. Never substitute that ASCII interval for file coverage.

Access is random and bounded to individual records; the entire binary is not
loaded. The reader uses a configurable bounded LRU record cache (four records
by default). Fetched records reject nonfinite coefficients and must have their
exact expected date span. Dates must be finite and covered. Coefficient slices
and interpolation subdivisions are bounds checked before access.
`maximumCachedRecords: 0` disables caching. Record IO and cache access are
serialized internally by a lock, so multiple providers can share a reader.
`clearRecordCache()` removes cached records; `cacheStatistics` exposes current
entry count and cumulative hit/read counts, including constructor validation.
LRU bookkeeping is linear in configured cache capacity; use modest limits.
There is no automatic fallback/extrapolation or Sendable conformance. The
underlying file must remain immutable while a reader is alive; create a new
reader after replacing an asset. A full-file integrity scan is not performed
at open time, and unread corrupt records are detected when queried.

## Optional local validation assets

Place the following files under `Data/DE441/`:

- `linux_m13000p17000.441`: native binary export.
- `testpo.441`: JPL's independently supplied reference rows.
- `header.441`: optional human-readable source header.

These assets are ignored by Git, excluded from SwiftPM resources and never
downloaded automatically. The library does not discover or require them:
applications pass a URL to data they own. Tests use a Swift Testing enabled
trait to run the local-data suite only when both binary and reference file
exist. To use another directory, set `CELMEK_DE441_DATA_DIRECTORY`; an explicit
missing directory also disables that suite. Missing assets do not fail builds
or tests. Present but malformed or inconsistent files do fail validation.

The normal local test compares a deterministic sample of every 83rd supported
covered row in `testpo.441` against the native reader, including all target
identifiers, vector positions/velocities and nutations throughout coverage.
Set `CELMEK_DE441_FULL_VALIDATION=1` to compare every supported covered row
(334,244 rows for the supplied export). A full scan took about 84 seconds in
the development debug build, so it is opt-in. The test
skips rows outside binary coverage and libration rows not yet exposed by the
reader. Absolute tolerance is `1e-12` in each row's native output units. The
synthetic suite always runs, including polynomial values/derivatives, Earth–Moon
reconstruction, internal/coverage boundaries and corrupt-header rejection.

```sh
swift test --disable-sandbox
CELMEK_DE441_DATA_DIRECTORY=/path/to/local/de441 swift test --disable-sandbox
CELMEK_DE441_FULL_VALIDATION=1 swift test --disable-sandbox --filter DE441LocalDataTests
```

Source data and format background are published by
[JPL](https://ssd.jpl.nasa.gov/planets/eph_export.html); physical model details
are in [Park et al., DE440/DE441 (2021)](https://ssd.jpl.nasa.gov/doc/Park.2021.AJ.DE440.pdf).
This repository stores test logic rather than redistributing the full data.
Applications should assess packaging and source attribution for their chosen
assets separately; the library's software license does not grant data rights.

## Split dates and the common ephemeris interface

Both vector and nutation queries accept `JulianDateComponents` tagged `.tdb`.
The reader locates records with integer day arithmetic, then interpolates using
only the small offset within a 32-day record. It never combines the split date
into a large Julian-date scalar during interpolation. The Double overloads
remain for compatibility; their inputs have already lost sub-ULP timing detail.
Exact internal boundaries use the following subdivision/record; the final
coverage endpoint uses the last one. Interpolation is still binary64 arithmetic
within a record, not an arbitrary-precision guarantee.

```swift
let reader = try DE441Ephemeris(url: fileURL, maximumCachedRecords: 8)
let provider = try DE441StateProvider(
    reader: reader, target: .earth, coverage: usableEpochRange,
    tdbModel: FairheadTDBModel(), accuracy: .balanced)
let state = try provider.checkedState(at: simulationEpoch)
```

`DE441StateProvider` conforms to `EphemerisProvider` and
`AccuracyAwareEphemerisProvider`; use it in an `EphemerisCollection`, with frame
conversion, or with the explicit state-cache and batch interfaces. The caller
selects epoch coverage that must lie within both file coverage and the injected
TDB model's coverage. File coverage does not certify time-model accuracy over
the full DE441 span. In particular, the full Fairhead model's declared coverage
is much narrower than the file. No less accurate time model is substituted
implicitly to widen coverage.

Output is metres and metres per atomic second, carrying the requested epoch
and declared frame. Velocity uses the analytic Chebyshev derivative, converted
from AU/TDB-day and multiplied by `dTDB/dTT` from the same validated time-model
sample used to obtain the TDB date. Acceleration remains unavailable.
All accuracy hints are accepted and evaluate the complete stored polynomial;
the effective level is `.full` and no terms are dropped.

The default centre is the solar-system barycentre and the default frame is
`CelestialFrames.icrf`. A different centre requires an explicit pseudo-inertial
frame with that origin and ICRF-aligned axes; frame identity alone cannot
verify this geometry. The adapter does not silently relabel ICRF vectors as
rotated axes. Query directly in a correctly registered centre frame, or request
barycentric states and convert through `FrameTree`. Metadata maps testpo body
numbers to `BodyIdentifier`, preserving planetary-system barycentre identities.
A non-ICRF frame supplied with an SSB centre is rejected; use explicit frame
conversion instead.

The reader is internally serialized. Concurrent adapter queries additionally
require a thread-safe injected TDB model. Queries are deterministic for fixed
file bytes/model inputs regardless of cache size or query order. Cache statistics
can depend on order; returned states do not. IO failures, unsupported bodies,
non-TDB low-level dates and uncovered queries propagate explicitly. A zero
vector for equal target/centre does not bypass date or body validation.

Synthetic tests retain a date difference that vanishes when combined into a
large JD, verify SI units with a deliberately non-unit TDB rate, exercise cache
limits/eviction/disable behavior, and query a shared reader concurrently. Local
asset tests also check the adapter at interior and record-boundary epochs and
compare its returned velocity with nearby positions using atomic time steps.

## Pinned independent references

`Tests/CelMekTests/Fixtures/de441-testpo.json` stores a small reproducible
selection of numerical values from JPL's independently supplied testpo file,
with its source URL and SHA-256. See `Fixtures/de441-reference.md` and
`Tools/extract_de441_reference_fixtures.py` for selection and regeneration.
Expected values are never produced by this reader. The pinned suite covers every
supported target/component, Earth/Moon/EMB and nutation record boundaries and
interiors, modern relative SI states, and widely separated epochs. It requires
only the optional binary, so it can run without the 23 MB testpo file. Fixture
structure/coverage checks always run. The complete testpo scan remains opt-in.

## Attribution, redistribution and game asset packaging

Keep the library's Apache-2.0 software notices separate from the provenance and
terms of the ephemeris data. This repository ships a small numerical regression
fixture, not the full native export, JPL source programs, or SPICE kernels.
Public download availability is not an additional data license from this
library. JPL's [SSD FAQ](https://ssd.jpl.nasa.gov/faq.html) points users to its
copyright statement; [Caltech/JPL's notices](https://www.jpl.nasa.gov/caltechjpl-privacy-policies-and-important-notices/)
state that server documents may be protected. Review the notices accompanying
the exact assets you distribute; do not infer a blanket commercial redistribution
grant from NASA sponsorship or an image-use policy. This documentation does not
supply a DE441-specific license determination.

An application credits its chosen source, for example:

> Planetary and lunar ephemeris data: NASA/JPL DE441, Park et al. (2021),
> *The JPL Planetary and Lunar Ephemerides DE440 and DE441*, Astronomical
> Journal 161, 105, doi:10.3847/1538-3881/abd414. Native little-endian export
> obtained from JPL Solar System Dynamics.

Store that attribution together with a data manifest: source URL, acquisition
date, exact filename, SHA-256, DE number, binary coverage, byte order and profile,
file size, units/frame/time conventions, and any subset-generation steps. Preserve
source notices. Attribution records provenance; it does not itself grant rights.

For game integration, keep DE441 in an optional asset pack or an application-owned
read-only file. The supplied long-span export is roughly 2.6 GB and should not be
added to this package's SwiftPM resources. Distribution systems may compress an
asset pack in transit; extract the native file before handing its URL to the
reader, which requires seekable random access. Use platform file URLs rather
than a hard-coded checkout path. If a file is bundled by an application, resolve
it through that application's bundle; the library does not own that bundle.

Verify download size/checksum during installation, then validate the file by
opening the reader before activating the pack. Install replacements under a new
path and switch to a new reader; never mutate an active reader's file. A bounded
record cache limits coefficient memory, not the asset's disk footprint. A
shorter export is usable only if its complete header/layout/coverage/file-length
contract matches the supported profile; arbitrary byte truncation is invalid.
A `.bsp` SPK asset cannot be renamed into a native `.441` export.

When no pack is installed, omit the DE tier and use the explicit
`FallbackEphemeris` model/Kepler tiers. Keep a present but invalid pack visible as
an installation/validation error. Neither runtime queries nor tests automatically
download data. CI without assets still runs synthetic format, derivative, cache,
contract and fallback tests; CI with the local binary also runs pinned independent
comparisons. Use `CELMEK_DE441_FULL_VALIDATION=1` for the release-time full-reference
scan when the optional testpo asset is available.
